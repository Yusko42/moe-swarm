# MoE Swarm — формализация QA-замеров

Набор документов по задаче **«QA, чек-листы: формализовать замеры»**.

| Артефакт | Назначение |
|---|---|
| [`methodology.md`](methodology.md) | Шесть требуемых показателей (с разделением близких метрик), единицы, границы, источники, правила повторов, настройка модели/кэша и ограничения |
| [`corpus/`](corpus/) | Искусственно созданные запросы: короткий, профили ~1k/~4k/near8k, многоходовый сценарий, генератор и манифест SHA-256 |
| [`checklists.md`](checklists.md) | До / во время / после прогона, стоп-условия |
| [`report-template.md`](report-template.md) | Протокол стенда, профиля, исходных замеров, среднего, медианы, доказательств |
| [`raw-runs-template.csv`](raw-runs-template.csv) | Необязательная заготовка машиночитаемых сырых строк |
| [`environment-manifest-template.json`](environment-manifest-template.json) | Заготовка манифеста версии сборки, модели и конфигураций трёх ПК |

**Статус:** документационный черновик v0.1. Достоверные измерения **не проводились**. Подписи ~1k/4k/8k у корпуса — некалиброванные профили; для допуска к испытаниям нужна реальная Qwen3-токенизация, конечный chat template и проверка общего лимита контекста. Цель `256` токенов сама по себе не гарантирует длину выхода; требуется зафиксировать поддерживаемое поведение EOS/ignore_eos.

## Применение в проекте

1. Скопировать содержимое `docs/qa/` в одноимённую папку репозитория.
2. Согласовать вопросы раздела 9 `methodology.md` с командой и зафиксировать версию движка/модели.
3. Калибровать корпус на *действительно используемом* токенизаторе/шаблоне. После этого зафиксировать SHA-256 и не перегенерировать файлы для уже начатой серии.
4. Использовать общие QA-чек-листы ФТ и шаблоны багов; новая методика не создаёт дублирующие функциональные тесты.
5. Для НФТ-1 официальный вход — **пробный запрос из Wiki**, а не случайный текст из `corpus/`.
