# Чек-листы подготовки и проведения замеров MoE Swarm

**Применять для каждого `run_group_id`.** Этот чек-лист не дублирует функциональные чек-листы ФТ-1–7 из общего «Плана тестирования». Проверки с одинаковыми предусловиями/действиями/ожидаемыми результатами не создавать повторно: ссылаться на уже существующую строку.

## До прогона

- [ ] Указаны `run_group_id`, дата/время с часовым поясом, исполнитель, `stand_id`, роль каждого ПК.
- [ ] Доступны спецификация стенда и манифест версии ПО/коммитов; бинарники каждого узла и движка соответствуют манифесту.
- [ ] Проверен SHA-256 **фактического GGUF-файла**; модель и квантовка соответствуют целевому сценарию.
- [ ] Зафиксированы тип/канальность RAM, CPU, ОС, SSD, версия движка, ограничения памяти и контекст 8192.
- [ ] Выбраны профили `COLD_PROMPT` либо `MULTITURN_CACHE`, условия прогрева/перезапуска описаны.
- [ ] Зафиксированы sampling (temperature/seed/top-k/top-p), отключение thinking проверено, лимит выхода 256 и stop/EOS-политика записаны.
- [ ] Корпус заморожен по SHA-256, токены проверены **финальным шаблоном и токенизатором**; `prompt_tokens_total + 256 <= 8192`.
- [ ] На всех ПК нет посторонней существенной нагрузки; состояние CPU, RAM, фоновых процессов записано.
- [ ] Соединение проводное; линк ≥1 Гбит/с; проверены доступность узлов, RTT и, если предусмотрено, throughput.
- [ ] Нет параллельных запросов в системе, где измеряется единичный ответ.
- [ ] Логи событий доступны; есть `request_id/run_id`, timestamp и источник timings (или записана блокировка `NOT INSTRUMENTED`).
- [ ] Подготовлен сбор памяти: cgroup v2 per-run или иной явно описанный счётчик, 1 с sampling, peak и swap (если доступно).
- [ ] Для холодного старта: старый процесс остановлен, endpoint `/health` не возвращает 200 до замера.
- [ ] Открыт `report-template.md`, назначены файлы raw-результатов, журналов и метрик.

## Во время прогона

- [ ] Записать t0/t1 и HTTP status для `server_startup_s`; отдельно `/start` → `model_ready` для НФТ-6.
- [ ] Сохранить `request_id`, выбранный corpus profile, `prompt_tokens_total`, число обработанных и кешированных токенов.
- [ ] Для TTFT записать t0 отправки и t1 первого непустого `content` (указать client/server источник).
- [ ] Сохранить оригинальные prompt/decode timings и количество токенов/декодирующих шагов.
- [ ] Снимать RAM с каждого узла каждые 1 с; сохранять time series, `memory.peak` и использованный предел.
- [ ] Для очереди записать `request_received`, `request_dequeued`, `response_started` и корреляцию запроса; не подменять очередь TTFT.
- [ ] Выполнить один warm-up отдельно, а затем 10 **учитываемых валидных** запросов, если сценарий требует 10; исключённые/ошибочные прогоны сохранить с причиной.
- [ ] Убедиться, что в фоне нет посторонних запросов; зафиксировать любые отклонения оборудования, сети или параметров.
- [ ] Для многопользовательских замеров очереди явно зафиксировать порядок и время отправки запросов каждого клиента.
- [ ] Не сохранять текст пользовательских запросов/ответов в технических журналах; вместо этого использовать `corpus_id` и SHA-256.

## После прогона

- [ ] Проверить количество валидных измерений, причины неуспешных и соответствие условий манифесту.
- [ ] Сохранить сырые ряды, исходные timestamps, counters, OS memory samples и stdout/stderr без секретов/диалогов.
- [ ] Рассчитать среднее, медиану и число ошибок, указав метод подсчёта и `n`.
- [ ] Проверить отсутствие попадания текста диалога, токенов доступа и других чувствительных данных в журнал.
- [ ] Остановить `llama-server`, RPC-серверы и процессы стенда, освободить память и сетевые ресурсы.
- [ ] Проверить, что больше нет подвисших процессов; сохранить доказательство завершения.
- [ ] Заполнить `report-template.md`, связать с НФТ, чек-листом и конкретной версией методики.
- [ ] При проблемах завести баг через общий QA-шаблон, приложить минимальные воспроизводимые факты.
- [ ] При отклонениях методики — явно указать их, не перезаписывая исходные результаты.

## Стоп-условия

- Невозможно установить, какая модель/сборка запущена или не совпадает SHA-256.
- Не удаётся определить истинное число входных токенов / вход+ответ превышают окно контекста.
- Есть существенная фоновая нагрузка либо нестабильность сети, способная исказить сравнение.
- Отсутствует обязательный источник метрики или журнал событий → соответствующий показатель `NOT INSTRUMENTED`, а не выдуманное число.
- Не пройден smoke-test основного сценария → прекращается последующее тестирование этой сборки согласно плану.
