# Синтетический корпус запросов MoE Swarm

- `control-short.txt`: короткий контрольный запрос для smoke/проверки измерителя.
- `dialogue-1k.txt`: целевой профиль около 1000 входных токенов.
- `dialogue-4k.txt`: целевой профиль около 4000 входных токенов.
- `dialogue-near-8k.txt`: профиль около 7800 токенов полного **подготовленного входа**, при ограничении контекста 8192 + резерв 256 на ответ.
- `multiturn.json`: фиксированная синтетическая многоходовая история (первые сообщения явно заданы; последний user-turn измеряемый).
- `manifest.json`: SHA-256, число синтетических строк, статус калибровки.
- `generate.py`: детерминированное пересоздание корпуса; опциональная калибровка через реальный API сервера.

**Внимание:** подписи 1k, 4k и near-8k у файлов — профили, а не уже измеренное число токенов. Без указанного `--server-url` генератор не знает реальные токены GGUF. Результаты нельзя считать воспроизводимыми, пока не проведена калибровка на финальном tokenizer + template, и окончательные файлы с хешами не заморожены в репозитории.

Примеры:

```bash
python3 docs/qa/corpus/generate.py
python3 docs/qa/corpus/generate.py --server-url http://127.0.0.1:8080
```

**Не перегенерировать корпус после проведения измерений без явной новой версии.** При любой модификации обязательны новые хеши и новая серия измерений.

Калибровка через API использует `/apply-template` + `/tokenize` по предлагаемому `SYSTEM`, но фактический запрос может применять другой chat template, hard-switch thinking, роли и специальные токены. Поэтому **итоговое** число входных токенов взять из системы, которая будет реально выполнять запросы (после всех обёрток и шаблонов), и проверить `actual_prompt_tokens + 256 <= 8192`.

Для официальной проверки НФТ-1 вместо этих текстов применяется **пробный запрос из Wiki**. Не смешивать серии контрольного корпуса и официального пробного запроса.
