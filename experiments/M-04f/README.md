# М-04f. Ревизия и параметры запуска llama.cpp

На Ubuntu 26.04.1 LTS в WSL2 собраны и проверены `llama-server` и `ggml-rpc-server` из чистого `external/llama` на коммите `cd959bae99ff4bed22bef2604f45241c09bbb8c8` (b12110, gitlink `origin/dev` на `e47271b353b660e4a746995f46b51fcc294bc0aa`).

Сборка Release, CPU + RPC, GCC 15.2.0, CMake 4.2.3, Ninja 1.13.2. `GGML_NATIVE=OFF`. AVX, AVX2, AVX-512, FMA, F16C, BMI2 и SSE4.2 отключены. Оба ELF объявляют `x86-64-baseline` и используют системные библиотеки GNU/Linux, включая libgomp и libstdc++. Проверка запуска проводилась на Intel Core i5-10300H. Совместимость с другими CPU и дистрибутивами и совпадение хэшей при независимой сборке не проверялись.

Обычный профиль использует `--load-mode none --split-mode layer -ngl 0 -c 8192 -np 1 -b 512 -ub 256 --no-context-shift -fa on --cache-type-k q8_0 --cache-type-v q8_0 --threads 4 --host 127.0.0.1 --no-slots`. В измерительном профиле добавляется `--metrics`. В обоих запусках эксперимента использован `-lv 4` для доказательств в журнале. Бинарник отвергает `--no-mmap`, поэтому применён `--load-mode none`.

| Проверка | Наблюдение |
|---|---|
| Готовность и генерация | `/health` вернул 200 в трёх запусках. Обычный запрос сгенерировал 8 токенов. |
| Слоты | `GET /slots` и `POST /slots/0?action=erase` с `--no-slots` вернули 501. |
| Метрики | `GET /metrics` вернул 200 с `--metrics` и 501 без флага. Снимок содержит gauge `llamacpp:requests_processing`. |
| Отмена | Контроль дошёл до 128 токенов за 28,29 с с `ignore_eos=true` и `stop_type=limit`. Клиент трижды закрыл сокет после 8 событий SSE при активном запросе. Журнал содержит `cancel task` и `release` с совпадающими ID. Gauge перешёл в ноль до подачи следующего запроса. |
| Общий префикс | Все три следующих запроса сгенерировали 8 токенов и совпали с контрольным ответом при температуре 0. В каждом из них 124 токена взяты из кэша, один обработан заново. |
| RPC | `-H 127.0.0.1 -p <порт> -t 4`, дисковый кэш выключен через отсутствие `-c`. Клиент с `--rpc 127.0.0.1:<порт> -ngl 99` сгенерировал 8 токенов. Лог загрузки показывает буфер модели RPC0 и 29/29 выгруженных слоёв. |
| Ключи RPC | `-m` и `--version` выводят ошибку неизвестного аргумента при коде выхода 0. Баннер запуска сообщает версию протокола сервера 8.0.1. В этом прогоне отдельный лимит процесса не применялся. |

Для проверенного режима оставляем отмену закрытием соединения, выключенные слоты и метрики только в измерительном профиле. Резервная очистка слота не понадобилась и отдельно не проверялась. Подтверждение относится к трём последовательным отменам с одним слотом в локальном CPU-режиме. Полный Э-03g, отмена при RPC-генерации и конкурентные запросы остались за пределами прогона.

Модель Qwen3-0.6B Q3_K_M выбрана из манифеста проекта. Доступных примерно 14 ГиБ RAM недостаточно для уверенного запуска Qwen3-30B-A3B с 13,7 ГиБ весов, контекстом 8192 и рабочими буферами. Результаты не подтверждают работу Qwen3-30B-A3B. Один компьютер с несколькими процессами не доказывает работу на нескольких физических узлах или характеристики LAN. Все серверы эксперимента слушали loopback.

## Воспроизведение

В каталоге репозитория, с установленными GCC, CMake, Ninja и Python 3.14:

```bash
git submodule update --init external/llama
artifact_dir=/root/m-04f-artifacts
mkdir -p "$artifact_dir"
curl --fail --location --retry 2 --max-time 600 \
    -o "$artifact_dir/Qwen3-0.6B-Q3_K_M.gguf" \
    https://huggingface.co/unsloth/Qwen3-0.6B-GGUF/resolve/50968a4468ef4233ed78cd7c3de230dd1d61a56b/Qwen3-0.6B-Q3_K_M.gguf
(cd "$artifact_dir" && printf '%s\n' '30bb9f9222cf58c076277879881a24e7127a10be32076d76d8c70f8defc01f5d  Qwen3-0.6B-Q3_K_M.gguf' | sha256sum -c)
bash experiments/M-04f/build.sh "$artifact_dir/build"
timeout 300 python3 experiments/M-04f/check.py "$artifact_dir/build/bin" \
    "$artifact_dir/Qwen3-0.6B-Q3_K_M.gguf" "$artifact_dir/check"
python3 experiments/M-04f/collect.py "$artifact_dir"
(cd "$artifact_dir/build/bin" && sha256sum -c /root/src/moe-swarm/experiments/M-04f/SHA256SUMS)
```

[Манифест](manifest.json) содержит флаги, размеры, хэши, временные отметки и результаты. [Журнал](runtime.log) содержит строки об отмене, освобождении слотов и RPC. Полные журналы прогонов, GGUF и сборка хранятся вне репозитория в `/root/m-04f-artifacts`. Конечные файлы в `/root/m-04f-artifacts/build/bin` не подвергались strip.
