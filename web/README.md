# Веб-клиент swarm

Статичная страница чата на русском языке. По умолчанию открывается макет
ФТ-7 на тестовых данных: **запросов к API нет**. Дополнительный режим
`?mode=live` проверяет POST + SSE через интерфейс И-2.

## Стек и согласование

- Vite 8 + TypeScript 5.9, обычные DOM-компоненты, CSS без фреймворка.
- ESLint + typescript-eslint; форматирование проверяет Prettier.
- Vitest — проверки SSE и транспорта; Playwright — браузерные сценарии.
- Node.js **24.22.1**, версия закреплена в `.nvmrc` и ограничена `engines`.
  Точные версии зависимостей записаны в `package.json` и `package-lock.json`.
- Причина выбора: небольшой клиент без runtime-зависимостей; для этой
  страницы достаточно типизированных DOM-компонентов. Vite предоставляет
  сборку с относительными путями и middleware для dev-заглушки.

**Статус согласования: предложено, не согласовано.** Требуется решение
[Егора Максимова](https://ai.nsu.ru/users/1062). Эта реализация не является
подтверждением согласования и не отправляет ему сообщений.

## Запуск

Команды выполняются из `web/`:

```sh
nvm install
nvm use
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173/`. Начальная страница: пустой диалог,
заголовок «Чат с роем», неактивная кнопка «Отправить».

Для проверки потока открыть `http://127.0.0.1:5173/?mode=live`, ввести
вопрос и отправить. Заглушка ждёт 900 мс в очереди, затем выдаёт токены
каждые 75 мс. Данные остаются на локальном сервере разработки.

## Сборка и подключение к swarm create

```sh
npm ci
npm run build
npm run preview
```

Проверка готовых файлов: `http://127.0.0.1:4173/`. Сборка находится в
`web/dist/`; в Vite установлен `base: './'`, поэтому ссылки на JS, CSS
и favicon относительные. Каталог можно разместить под URL-префиксом.
Страницу нужно открывать через HTTP, а не двойным щелчком `file://`:
браузеры ограничивают загрузку ES-модулей с файловой системы.

HTTP-сервер `swarm create` должен раздавать содержимое `web/dist/`,
возвращая правильные MIME-типы. Корневые маршруты `/api/v1/*` должны
обслуживаться программой swarm на **том же origin**. Перенаправлять API
на HTML страницы нельзя. Полный URL API не настраивается намеренно:
обращений к llama-server или внешним сервисам нет.

`npm run preview` раздаёт только статические файлы. Заглушка туда не
подключена. Для SSE в preview нужен настоящий сервер И-2; без него режим
подключения покажет ошибку и вернёт вопрос в поле ввода. Сам макет и
все состояния работают без API и без интернета.

Исходного C++-репозитория и программы `swarm create` в рабочем каталоге
не было. Настройка конкретного HTTP-сервера и проверка на реальном swarm
не выполнены; дерево файлов подготовлено для переноса в корень репозитория.

## Состояния макета

Выбираются верхним переключателем или параметром `?state=…`.
Параметр сохраняется при смене состояния и после обновления страницы.
Это снимки вёрстки: текст потокового ответа в них фиксирован.
Кнопки «Отправить», «Остановить», «Отменить» показывают требуемый вид
и доступность; для их транспортной демонстрации есть отдельный SSE-режим.
«Новый диалог» сбрасывает макет. Поле ввода можно редактировать.

| `state`         | Состояние                   | Основная кнопка             | Новый диалог |
| --------------- | --------------------------- | --------------------------- | ------------ |
| `empty`         | Пустое поле                 | Отправить, неактивна        | Активна      |
| `ready`         | Готов к отправке            | Отправить                   | Активна      |
| `queued`        | В очереди                   | Отменить                    | Неактивна    |
| `streaming`     | Идёт ответ                  | Остановить                  | Неактивна    |
| `done`          | Ответ завершён              | Отправить                   | Активна      |
| `stopped`       | Ответ остановлен            | Отправить                   | Активна      |
| `limit`         | Предел диалога              | Отправить                   | Активна      |
| `error`         | Ошибка до начала ответа     | Отправить, вопрос возвращён | Активна      |
| `rebuilding`    | Перестройка во время ответа | Остановить                  | Неактивна    |
| `retrying`      | Повтор после перестройки    | Остановить                  | Неактивна    |
| `model-stopped` | Модель остановлена          | Отправить                   | Активна      |
| `disconnected`  | Связь потеряна              | Отправить                   | Активна      |
| `disbanded`     | Рой распущен                | Отправить                   | Активна      |

В финальных статичных снимках в поле уже введён следующий тестовый вопрос,
поэтому «Отправить» активна. Пустое или пробельное поле блокирует кнопку
во всех состояниях, допускающих отправку.

Варианты ошибки: `?state=error&error=5.2`, `5.3`, `5.4`, `5.5`,
либо второй переключатель. **Точные тексты этих пунктов не предоставлены**:
в макете явно показаны тестовые подписи, требующие замены после сверки
с полным ФТ-7. Тексты для перестройки 9.1 и роспуска также требуют
проверки по первоисточнику: в задании для них нет дословных формулировок.

## Структура

| Файл                   | Назначение                                                            |
| ---------------------- | --------------------------------------------------------------------- |
| `src/ui/components.ts` | Диалог, сообщение, строка уведомлений, поле ввода, кнопки, заполнение |
| `src/ui/states.ts`     | Все снимки состояний и тестовые тексты                                |
| `src/main.ts`          | Компоновка страницы и переключение макета                             |
| `src/live.ts`          | Изолированная демонстрация подключения транспорта                     |
| `src/api/events.ts`    | Все временные wire-типы И-2 и проверка payload                        |
| `src/api/sse.ts`       | Потоковый парсер SSE                                                  |
| `src/api/chat.ts`      | POST через fetch, проверка ответа и порядка событий                   |
| `dev/mock-api.ts`      | Dev-заглушки `/api/v1/chat`, `/state`, `/swarm`                       |

Роли пользователя и модели размечены отдельно. Текст вставляется через
`textContent`, без HTML и Markdown: ответ модели не может вставить
исполняемую разметку, внешние изображения или скрипты. Длинные слова
переносятся; область диалога прокручивается независимо от поля ввода.
Есть подписи полей, клавиатурный фокус и режим уменьшения анимации.

## Временный контракт И-2

Контракт **не утверждён**. После согласования заменить wire-типы и
декодер в `src/api/events.ts`; при изменении семантики событий обновить
обработчики в `src/live.ts`, mock и тесты.

Запрос: `POST /api/v1/chat`, `Content-Type: application/json`,
`Accept: text/event-stream`.

```json
{ "prompt": "Вопрос", "conversation_id": "необязательный-id" }
```

Ответ: `Content-Type: text/event-stream; charset=utf-8`.
Тип передаётся в поле `event:`, JSON — в поле `data:`.

| Событие    | JSON в `data`                                                                        |
| ---------- | ------------------------------------------------------------------------------------ |
| `accepted` | `{"request_id":"mock-1","position":2,"reason":"Все исполнители заняты"}`             |
| `started`  | `{"request_id":"mock-1"}`                                                            |
| `token`    | `{"text":"Фрагмент ответа "}`                                                        |
| `done`     | `{"tokens_per_second":13.3,"predicted_tokens_per_second":15.2,"context_percent":12}` |

Поддерживается последовательность `accepted → started → token × N → done`.
До `started` возможны повторные `accepted` для обновления позиции очереди.
Поддерживаются UTF-8 на границах чанков, многострочные `data:`, комментарии
SSE и окончания строк LF/CRLF/CR. Поток без `done` считается оборванным.
Автоматического повтора POST нет: он мог бы создать дублирующий запрос.

`GET /api/v1/state` возвращает тестовый `{"status":"ready"}`;
`GET /api/v1/swarm` — `{"status":"active","nodes":4}`. Клиент не опрашивает
эти маршруты: их семантика пока не задана. Заглушка принимает только
указанные методы и отклоняет пустые/некорректные запросы.

SSE-демо отправляет только `prompt` и не реализует серверную историю
диалога. Новый диалог сбрасывает локальную страницу. «Остановить» и
«Отменить» вызывают `AbortController`: закрывается HTTP-поток клиента.
Остановка вычисления или удаление запроса на сервере этим не гарантируется.
Для них нужны утверждённые операции И-2. Перестройка, лимит контекста,
распуск и потеря модели представлены статичными снимками; соответствующие
серверные события нельзя придумывать до утверждения контракта.

## Проверки и CI

```sh
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:ui
```

`lint` запускает ESLint и `prettier --check .`; исправление форматирования:
`npm run format`. Браузерные тесты запускают оба сервера сами. Порты 5173
и 4173 должны быть свободны. Если Chromium уже установлен, можно задать
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` вместо загрузки браузера.

В `../.github/workflows/web.yml` — отдельная задача с `npm ci`, линтером,
unit-тестами, сборкой и браузерными проверками. Зависимостей от задач C++
нет. Перед переносом адаптировать путь workflow, если хостинг репозитория
использует не GitHub Actions. `dist/`, `node_modules/`, отчёты тестов и
покрытие исключены через корневой `.gitignore`.

Страница не использует CDN, внешние шрифты, аналитику или сетевые
иллюстрации. Иконки локальные, шрифты системные. Интернет нужен для
первоначальной установки npm-зависимостей и браузера для тестов; для
работы собранной страницы он не нужен. Dev-сервер использует локальный
WebSocket Vite для HMR.
